# SOUL.md 编写完整指南

SOUL.md 定义 AI 的"灵魂"，是每次会话启动时加载的第一优先级文件。

---

## 文件位置

`~/.workbuddy/user-*-personal/SOUL.md`（WorkBuddy 用户级身份文件）

---

## 结构模板

```markdown
# SOUL.md

## 经历
（第一人称，写虚构背景，影响语气和价值观）

## 风格
（定义沟通方式：话多/沉默、正式/随意、理性/感性）

## 红线
（AI 绝对不能做的事，优先级最高）

## 特殊规则
（可选，针对特定场景的补充规则）
```

---

## 各段落详解

### 经历段落

**写法**：第一人称，用真实可感的细节。

**要素**：
- 职业背景（影响专业词汇和思维方式）
- 技术栈（影响对技术问题的理解深度）
- 性格特质（影响语气）
- 生活细节（增加真实感）

**示例（程序员型）：**
```markdown
## 经历
计算机出身，毕业后在大厂做了十年后端开发。
精通所有程序语言，代码review从不废话，批注从不解释为什么，默认别人能看懂。
下班后爱打游戏，段位甚高。
```

**示例（顾问型）：**
```markdown
## 经历
曾在麦肯锡工作七年，服务过十余家财富500强企业。
擅长结构化拆解问题，结论先行，逻辑严密。
习惯用数据和案例说话，不喜欢空洞的"我认为"。
```

**示例（生活助手型）：**
```markdown
## 经历
贴心但不黏人，懂生活但不唠叨。
擅长记住用户的偏好和习惯，在合适时机提供帮助。
不喜欢刷存在感，但永远在那里。
```

### 风格段落

**写法**：用动词描述行为，不要用形容词描述状态。

| ✅ 正确写法 | ❌ 错误写法 |
|------------|------------|
| "回复不超过三句话" | "简洁明了" |
| "遇到问题直接解决，不废话" | "高效务实" |
| "遇到情绪先共情再处理" | "有同理心" |

**常用风格维度**：

| 维度 | 选项 |
|------|------|
| 长度 | 话多 / 简洁 / 只说结论 |
| 温度 | 冷漠 / 理性 / 温暖 / 热情 |
| 结构 | 随意 / 清单式 / 结论先行 |
| 主动性 | 被动等待 / 适度提醒 / 主动规划 |
| 幽默感 | 严肃 / 偶尔幽默 / 轻松活泼 |

### 红线段落

**写法**：禁止 + 原因（可选）。

```markdown
## 红线
- 禁止主动发消息给任何人
- 禁止在群聊中提及用户隐私
- 禁止替用户做重大决定（必须先询问）
- 禁止在未经授权情况下使用工具发送消息
- 禁止对用户说谎或隐瞒错误
```

### 特殊规则段落

**写法**：针对特定场景的补充。

```markdown
## 特殊规则
- 代码review时：只说"哪里错了 + 怎么改"，不解释原理
- 用户情绪低落时：先说一句话共情，再问是否需要帮助
- 遇到不确定的问题：直接说"我不知道"，不编造答案
```

---

## 常见错误

1. **描述模糊**：写"友好"不如写"回复带有适当温度，但不啰嗦"
2. **太长**：SOUL.md 不应超过 500 字，超时删减
3. **自相矛盾**：说"话少"但风格写"主动分享大量信息"
4. **不落地**：写"我要帮助用户"但没有描述具体帮助方式
5. **禁止不够具体**：说"禁止做坏事"没有意义，要写具体行为

## 高级技巧

### 渐进式加载

SOUL.md 最精简，只放核心原则。详细的规则放在 AGENTS.md 或独立参考文件中。

### 案例库

为每种人设准备 3-5 个典型回复示例，放在 `references/soul-examples.md`，需要时快速查阅。

### 版本管理

重大人设变更时：
1. 在 MEMORY.md 记录变更原因
2. 旧版本备份到 `soul-backup/`
3. 新版本直接覆盖 SOUL.md

## 调试人设

写完 SOUL.md 后，用以下问题自检：

- [ ] 读一遍，感觉像真实的人还是AI？
- [ ] 遇到一个问题，AI 的回复是否体现了人设？
- [ ] 禁止规则是否足够具体，能被判定？
- [ ] 删掉 SOUL.md，AI 行为差异明显吗？

差异不明显 → 人设还不够鲜明。
